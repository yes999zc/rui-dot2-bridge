## 四、设备端唤醒（device_wake）的真相

插头侧已实现完整 v1 路径，但**设备今天还不能自己打分**：

- EchoMuse 固件**不含** OWW 运行时与模型（em_oww_assets：ONNX Runtime 12.3 MB + 特征模型 + 分类器），
  必须由控制器推送到设备 /app/models/oww_runtime，并用 config 下发 owwModel + owwOnDevice=on；
- stock 模型只有英文（hey_jarvis_v0.1 / alexa_v0.1）；中文"你好小瑞"需用 oww_forge 自训 ONNX；
- 设备 register 已带 oww_local_only/oww_shadow/oww_trigger（固件具备能力），但 listen_state=stream
  （现在由 rui KWS 检测），所以 probe 诚实上报"无 device_wake"，rui 降级 KWS（device_wake_fallbacks=1）。

三条路线与建议见 [p4-device-wake-feasibility.md](p4-device-wake-feasibility.md)。

## 五、部署形态（可复现）

- 下游镜像：deploy/downstream/Dockerfile（FROM ghcr.io/yes999zc/rui:0.3.4，COPY 插件 + 两个 ENV）。
  注意：构建要用宿主机 x86_64（本机构建会卡在 BuildKit 并发，最后用 DOCKER_BUILDKIT=0 一次成功）。
- manifest 双份：镜像内（loader 门控）+ <data_dir>/plugs/dot2-echomuse（catalog 与 wake 策略读这份；
  缺这份且设了 params.plug_id 会 fail-closed 回 KWS）。脚本：deploy/downstream/install-plug-manifest.sh。
- compose 用 deploy/downstream/docker-compose.yml（host 网络、read_only、1000:1000、/config 与 /var/lib/rui 挂载、
  dot2-secrets 只读挂载）。宿主上已去掉 build 段（镜像预构建）。
- 设备配置由官方 POST /api/v1/setup/device 写入；manifest 的 runtime.listen_port=8870、token_env=DOT2_EM_TOKEN
  作为缺省值；X-EM-Token 实际从 /opt/rui-secrets/device_token 读取（日志只记 source: file）。
- 回滚：~/rui/docker-compose.yml.vanilla-0.3.4（vanilla）、RUI_IMAGE=ghcr.io/yes999zc/rui:0.2.2（旧版，保留 uid 1000）。
